## 실제 Firebase 검증 결과

- 할 일을 추가하고 저장 성공 후 입력이 비워지며 목록에 표시되는 것을 확인했습니다.
- `serverTimestamp()`로 저장하고 최신 항목이 위에 표시되는 것을 확인했습니다.
- 한 창에서 추가한 항목이 두 번째 창에도 새로고침 없이 표시됐습니다.
- 완료·미완료 상태 변경과 두 창 사이 자동 반영을 확인했습니다.
- 삭제 검증 전용으로 만든 임시 항목을 삭제하고, 두 창에서 해당 항목만 사라지는 것을 확인했습니다.
- 새로고침 후 저장된 데이터가 유지됐습니다.
- 전체·진행 중·완료 필터와 `/completed` 페이지가 실제 데이터에서 올바르게 동작했습니다.
- `/completed` 직접 새로고침 후에도 완료 항목만 표시됐습니다.
- 완료 페이지에서 진행 중 필터를 선택하면 `/`로 이동했습니다.
- 다크/라이트 전환 및 새로고침 후 테마·필터 복원을 확인했습니다.
- 공백만 입력했을 때 추가 버튼이 비활성화되고 문서가 생성되지 않았습니다.
- 규칙 게시 후 새로 연 검증 창에서 브라우저 warning/error 기록이 없었습니다.

초기 접근 차단 규칙에서 실제 읽기 거부 안내도 확인했습니다. 규칙 게시 전 시뮬레이터에서는 `todos` 읽기 허용과 다른 경로 읽기 차단을 확인했습니다. 자동 테스트 26개는 SDK 모의 환경에서 오류·중복 요청 처리까지 별도로 검증합니다.

## 승인된 공동 목록 접근 범위

로그인 없는 과제용 공동 목록입니다. 승인에 따라 누구나 `todos` 항목을 읽고 추가·완료 변경·삭제할 수 있으며, 다른 경로는 차단합니다. 필수 필드·자료형·500자 제한·서버 타임스탬프를 검사하고, 수정 시 완료 상태만 변경할 수 있도록 제한했습니다.

접근은 **2026년 11월 14일 오전 9시(한국 시간)**에 만료됩니다. 이후에는 규칙을 다시 검토해 적용해야 합니다. 이 날짜는 보안 규칙의 만료일이며 Spark 요금제의 종료일이 아닙니다.
